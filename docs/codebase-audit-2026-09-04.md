Codebase audit, 4 September 2026

I reviewed the current working tree across the desktop app, API, mobile app, shared packages, build configuration, tests, and custom lint tooling. The scan covered roughly 34,500 lines of authored TypeScript, TSX, and CSS. Generated declarations, generated routes, dependencies, and build output were excluded from cleanup recommendations. Existing uncommitted changes were included in the review and left untouched.

There are 19 actionable findings below. The most urgent concern is Workspace lifecycle behavior. The largest deletion opportunity is the custom lint type-analysis code.

Validation passed: `vp install`, `vp check`, all 182 tests, and `vp run -r build`. The recursive test run initially could not start the API runtime inside the sandbox; its 26 tests passed when rerun with the required localhost access. `vp env doctor` passed. The other suites passed 120 desktop, 17 domain, 10 Workspace, and 9 mobile tests.

The date-validation mismatch and query-cache retention were checked with small executable reproductions using the installed dependencies. Other behavioral findings follow from the source and caller paths. I did not run an interactive Electron session or benchmark a large Collection.

The following nine findings affect behavior, performance, or failure diagnosis. P1 means fix first; P2 means a concrete issue worth scheduling.

1. **P1. Refreshing a sync credential tears down the local Workspace UI.** [workspace-startup.tsx:252](/Users/alexandrebessa/Downloads/mooligan/apps/desktop/src/features/workspace/workspace-startup.tsx:252) includes the credential, sync issue, and Workspace list in the equality check that decides whether to close the entire session. A change replaces the application subtree with a loading screen and disposes its StoreRegistry. Credentials last five minutes, and the renderer refreshes them one minute before expiry. A signed-in user can therefore lose an open dialog or unsaved component state roughly every four minutes. Account and sync metadata should update without replacing the local Workspace session. The installed LiveStore adapter treats the initial sync payload as an invariant, so this needs a deliberate transport/lifecycle change, not just deleting the comparison. Verify credential renewal while editing a Holding and loss of Account connectivity while using the local Collection. See [the close path:102](/Users/alexandrebessa/Downloads/mooligan/apps/desktop/src/features/workspace/workspace-startup.tsx:102), [credential lifetime:16](/Users/alexandrebessa/Downloads/mooligan/apps/api/src/sync.ts:16), and [ADR 7:28](/Users/alexandrebessa/Downloads/mooligan/docs/adr/0007-run-livestore-in-the-electron-renderer.md:28).

2. **P2. Collection query keys omit the Workspace identity.** [use-collection.ts:61](/Users/alexandrebessa/Downloads/mooligan/apps/desktop/src/features/collection/use-collection.ts:61) keys data by spoiler visibility and filters. The QueryClient survives Workspace replacement, and [collection-projection.tsx:64](/Users/alexandrebessa/Downloads/mooligan/apps/desktop/src/features/workspace/collection-projection.tsx:64) only invalidates those queries after the new projection is ready. Invalidation retains cached data. Switching between Workspaces with matching filters and spoiler settings can expose the previous Workspace's Holdings while the new request runs. A QueryObserver reproduction returned Workspace A's cached Holdings as its first result after invalidation. Include `workspaceId` in Collection query keys and test switching between two Workspaces with different Holdings. The existing `removeQueries` call handles worker resynchronization, not ordinary Workspace changes.

3. **P2. Repeated Collection schemas already accept different data.** [backup.ts:114](/Users/alexandrebessa/Downloads/mooligan/packages/workspace/src/backup.ts:114) accepts a date when a regex matches and `Date.parse` returns a finite number. [collection.ts:74](/Users/alexandrebessa/Downloads/mooligan/packages/domain/src/collection.ts:74) uses a stricter ISO datetime validator. I reproduced a backup containing `2026-02-31T00:00:00Z` passing the backup validator and failing the projection validator. A valid September date passed both. The LiveStore event schema has another, weaker string constraint. This allows restore validation to succeed before the Collection projection rejects the restored lot. Share field definitions and semantic constraints across the required representations, and reject malformed backup data before activating the restored Workspace. Finish, language, and condition are also repeated in [schema.ts:13](/Users/alexandrebessa/Downloads/mooligan/packages/workspace/src/schema.ts:13) and renderer types.

4. **P2. A migrated Button caller overwrites the wrapper's base styles.** [search-results.tsx:260](/Users/alexandrebessa/Downloads/mooligan/apps/desktop/src/features/search/search-results.tsx:260) spreads `stylex.props(styles.moreButton)` into the new Button. That passes a runtime `className`, despite the TypeScript props omitting that property. [button.tsx:46](/Users/alexandrebessa/Downloads/mooligan/apps/desktop/src/components/ui/button.tsx:46) spreads those props after its computed base, variant, and size classes, replacing them. Use the wrapper's existing `style={styles.moreButton}` API and inspect the load-more button's normal, focus, and disabled states. This finding concerns the current uncommitted UI migration.

5. **P2. Every catalog worker lookup copies the full Collection before checking whether the worker already exists.** [ipc.ts:616](/Users/alexandrebessa/Downloads/mooligan/apps/desktop/electron/catalog/ipc.ts:616) constructs the worker startup payload before its early return. [projection.ts:89](/Users/alexandrebessa/Downloads/mooligan/apps/desktop/electron/collection/projection.ts:89) materializes the entire lot map as an array. Catalog list, detail, and artwork-source requests repeatedly pay this cost even when they reuse the same worker. Check the worker identity first; take the Collection snapshot only when constructing a worker. This is an avoidable O(number of lots) allocation per lookup.

6. **P2. Every downloaded image triggers a complete disk-cache scan.** [image-cache.ts:303](/Users/alexandrebessa/Downloads/mooligan/apps/desktop/electron/catalog/image-cache.ts:303) waits for eviction after each download. [The eviction routine:385](/Users/alexandrebessa/Downloads/mooligan/apps/desktop/electron/catalog/image-cache.ts:385) lists the entire cache and performs a sequential `stat` for each image before checking whether the byte limit was exceeded. Filling an initially empty cache with N images performs roughly N squared file-stat work until capacity is reached. Track the cache byte total after an initial inventory and update it on writes and deletes, so full scans do not sit on every download's completion path. Measure filesystem calls during a gallery fill and retain the existing capacity/eviction tests.

7. **P2. Editing one Holding repeatedly reads the entire Collection.** [collection-mutations.ts:23](/Users/alexandrebessa/Downloads/mooligan/apps/desktop/src/features/collection/collection-mutations.ts:23) calls the all-lots query and then uses `find` or `some` for single-lot and Holding lookups. Add, remove, and update repeat this before and after committing. The table already has the relevant identifiers and a Holding index. Use targeted table queries for the lot ID or Holding key, preserving the unattributed-lot checks and post-commit validation. This removes whole-Collection work from routine edits without introducing a repository abstraction.

8. **P2. Several visible controls present unfinished behavior as working functionality.** [printing-prices.tsx:17](/Users/alexandrebessa/Downloads/mooligan/apps/desktop/src/features/cards/printing-prices.tsx:17) always renders `$0.00` without price data. [global-search.tsx:80](/Users/alexandrebessa/Downloads/mooligan/apps/desktop/src/components/global-search.tsx:80) updates local text and animated controls but never searches or navigates. [index.tsx:13](/Users/alexandrebessa/Downloads/mooligan/apps/desktop/src/routes/index.tsx:13) permanently displays “Loading Home” with no operation that can finish. Display unavailable prices honestly, connect global search to the existing search route, and give Home an actual empty state or redirect. The global-search finding concerns the current uncommitted component.

9. **P2. Failure paths discard the information needed to diagnose them.** [ipc.ts:672](/Users/alexandrebessa/Downloads/mooligan/apps/desktop/electron/catalog/ipc.ts:672) throws away the error returned by the query worker; the worker error callback also ignores its Error argument. [workspace-startup.tsx:268](/Users/alexandrebessa/Downloads/mooligan/apps/desktop/src/features/workspace/workspace-startup.tsx:268) explicitly receives and discards both the exception and React error information. Runtime refresh failures do the same. Preserve the underlying cause and operation in diagnostic logs while keeping concise user-facing messages. Otherwise schema errors, database failures, and worker crashes collapse into the same unhelpful message.

Two further changes would make future maintenance and verification more reliable.

1. **Replace source-text lifecycle assertions with behavior checks.** [workspace-lifecycle.test.ts:15](/Users/alexandrebessa/Downloads/mooligan/apps/desktop/test/workspace-lifecycle.test.ts:15) verifies a JSX regex and the absence of old identifier names. It cannot establish the registry lifetime promised by the test name and passes with the credential-refresh teardown above. Exercise suspension, retry, credential refresh, and unmount through the actual lifecycle boundary. Similar source-name assertions in Workspace backup/storage tests should be limited to deliberate architectural rules rather than treated as proof of runtime behavior.
2. **Separate catalog IPC registration from download and worker lifecycle code.** [catalog/ipc.ts:1](/Users/alexandrebessa/Downloads/mooligan/apps/desktop/electron/catalog/ipc.ts:1) has 780 lines covering IPC handlers, streaming downloads, progress, catalog replacement, import workers, query workers, and pending-request maps. These responsibilities have different failure and lifetime rules. Extract the existing download/import flow and query-worker client into focused modules, keeping IPC registration thin. Keep the existing typed operations and boundary validation; a generic RPC framework would add more complexity than this needs.

I would fix the Workspace lifecycle, Collection cache identity, and schema mismatch first. The unused exports, duplicate spinner, forwarding validators, and impossible spoiler states can then be removed in small changes. The lint subsystem deserves its own deletion/reduction change because it changes repository policy.
